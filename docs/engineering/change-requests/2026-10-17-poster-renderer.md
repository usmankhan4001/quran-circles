# Change request: posters (WP16) in the API, the worker and the contract

Requested by: renderer
Contract: API (new endpoints and schemas), scopes (new actions), messages (deep link: none new), i18n keys (`poster.*`), schema (two small columns)
What I need: the API and the worker to drive the renderer (`apps/poster-renderer`), so that admins and coordinators in scope can make posters and see when one is out of date. The renderer is built and tested; today only `pnpm --filter @qc/poster-renderer render:sample` drives it, with synthetic data. The contract has `POSTER_FORMATS`, `POSTER_STATUSES` and the `poster_templates` / `posters` tables, but no endpoints, request or response shapes, scope actions or queue.

Why: without them no client can make a poster, and the out-of-date flag (brief deliverable 6) cannot reach the console or the admin app.

Proposed change:

1. **Scopes** (`packages/contracts/src/scopes.ts`): `poster.create` and `poster.read`, staff, resource `venue` (the session's venue), roles: every admin and coordinator role that holds the venue (product decision: "Admins and coordinators in scope can make posters").
2. **Schemas** (move from `apps/poster-renderer/src/` into `@qc/contracts`, unchanged, so the API, the worker and the renderer share one copy):
   - `PosterSourceSnapshot` (= `SourceSnapshot` in `apps/poster-renderer/src/snapshot.ts`): `sessionId`, `sessionVersion` (the session's `updatedAt`), `localStartTime`, `durationMinutes`, `daysOfWeek`, `startsOn`, `endsOn`, `timezone`, `venue { id, name: Localized, area: Localized | null }`, and the function `posterOutOfDate(made, current): ('time' | 'venue')[]` (= `outOfDate`; its rules and tests are in `snapshot.ts` / `snapshot.test.ts`).
   - `PosterTemplateId` (`'cloud' | 'night'`), `PosterLanguage` (`'en' | 'ur' | 'en_ur' | 'ur_en'`), `PosterAccent` (`'tanzeem' | 'deep' | 'night'`), `PosterFields` (`title {en?, ur?}` max 80, `details {en?, ur?}` max 140, `accent`, `qrTarget: 'register' | 'session'`), all as in `apps/poster-renderer/src/input.ts` (control and bidi override characters refused).
   - `RendererRenderRequest` / `RendererRenderResponse`: the renderer's own HTTP body (`POST /render`), so the worker can call it with validated shapes.
3. **Endpoints** (api-core):
   - `adminPosters.templates` `GET /admin/poster-templates`: the active rows of `poster_templates` (id, key, names, formats, provisional).
   - `adminPosters.create` `POST /admin/sessions/{sessionId}/posters` body `{ templateKey, language, formats: PosterFormat[], fields }`: checks `poster.create` on the session's venue, builds the snapshot from the session, inserts one `posters` row per format with `status: 'queued'`, `source_snapshot`, `fields`, `locale` (the leading language), and enqueues one `poster-render` job. Answers 202 with the rows. Errors: `forbidden`, `not_found`, `validation_failed`, `rate_limited`.
   - `adminPosters.list` `GET /admin/sessions/{sessionId}/posters`: the rows with `status`, a download URL when `ready`, and **`outOfDate: { reasons: ('time'|'venue')[] } | null`**, computed by comparing each row's `source_snapshot` with the session now (`posterOutOfDate`). The console and the admin app show the "out of date" band and a Regenerate action from this.
   - `adminPosters.regenerate` `POST /admin/posters/{posterId}/regenerate`: same fields and template, a fresh snapshot, a new queued row (the old row stays until the new one is ready, then is deleted with its file).
   - `adminPosters.file` `GET /admin/posters/{posterId}/file`: streams the stored file (or redirects to a signed URL, depending on the storage the platform lane picks).
   - Share cards (WP17, "invite friends and family") reuse `adminPosters.create`'s pipeline with `formats: ['link_preview']`, or a public `GET /share/sessions/{sessionId}.png` that serves the latest `link_preview` for the `og:image` tag. The user-app lane should say which it prefers.
4. **Worker** (messaging lane): queue `poster-render` (pg-boss, retry 3 with backoff, expire 120 s, dead letter like `outbox-send`). The handler posts the request to `RENDERER_URL/render` with `Authorization: Bearer RENDERER_TOKEN`, stores each file under the key the renderer's `runPosterJob` uses (`posters/<sessionId>/<cacheKey>.<png|pdf>`, content-addressed, so a retry is harmless), and sets the row's `storage_key`, `status: 'ready'` (or `failed` with the code: `text_too_long` is not retried; `busy`, `render_timeout` and `render_failed` are). Reference implementation: `apps/poster-renderer/src/job.ts`.
5. **Schema** (`packages/db`): `posters.failure_code text null` (the code above, so the console can say "shorten the title" rather than a bare "failed"), and `posters.alt_text jsonb null` (the plain sentence per language the renderer returns, for the share sheet and the preview tag; poster direction, "Accessibility of images").
6. **i18n** (`packages/i18n`): move the renderer's `poster.*` keys into the shared catalogue, English and Urdu (Urdu drafts, with the review marker): `poster.scanToRegister`, `poster.scanToOpen`, `poster.dailyAt`, `poster.onDateAt`, `poster.listAnd`, `poster.listComma`, `poster.period.morning|noon|evening|night|lateNight`, `poster.alt`. Exact values are in `apps/poster-renderer/src/strings.ts`. The console and admin app need their own keys for the poster screens (template picker, out-of-date band, Regenerate); that is their lanes' list.
7. **Environment** (api and worker): `RENDERER_URL` (internal, e.g. `http://poster-renderer:8090`) and `RENDERER_TOKEN` (shared secret, generated on the server). The renderer reads `RENDERER_TOKEN` and `PUBLIC_WEB_BASE` (see `docs/agents/status/renderer.md` for the full list).

Affected lanes: contracts (scopes, schemas, endpoints, db columns, i18n keys), api-core (endpoints, out-of-date flag), messaging (worker queue), platform (service, storage, env), console and admin-app (poster screens), user-app (share card / link preview).

Workaround meanwhile: the renderer keeps its own copies of the schemas, the snapshot comparison and the strings, and is driven by `src/cli/render-sample.ts` with synthetic sessions. Nothing in `apps/api`, `apps/worker` or `packages/*` was changed. When the contract lands, the renderer imports the shared schemas and deletes its copies (a small follow-up in `apps/poster-renderer`).
