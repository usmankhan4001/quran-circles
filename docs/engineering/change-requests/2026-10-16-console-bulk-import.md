# Change request: bulk import with a dry run and one transaction

Requested by: console
Contract: endpoints (`packages/contracts/src/endpoints.ts`), schemas (`schemas/admin.ts`)
What I need: one commit call per kind of import that applies a whole file in a single transaction, and a `dryRun` mode that runs the same checks and changes nothing. Suggested ids: `adminImport.venues`, `adminImport.coordinators`, `adminImport.sessions`, each `POST /v1/admin/import/{kind}` with body `{ dryRun: boolean, rows: VenueCreate[] | InviteBody[] | SessionCreate[] }` (at most 2000 rows). The response lists, per row index, `created | duplicate | invalid` and the invalid rows carry `issues: { path, code }[]` in the same shape as `validation_failed`.
Why: the console cannot offer a safe import without it. Today the console parses and checks the file in the browser, then calls `adminVenues.create`, `adminRoles.invite` or `adminSessions.create` once per row, in file order, and stops at the first failure. That is not atomic: a network drop leaves a partial import, and each row is a separate audit entry and a separate rate-limit hit. The ui screen spec (`docs/design/screens/console-bulk-import.md`) already assumes "one transaction" and a server-side dry run, and says the console should never trust its own parse.
Proposed change: add the three endpoints (or one endpoint with a `kind` discriminator). Server checks scope with the same `can(...)` rules as the single create calls, treats an existing venue (same city and name), session or pending invite as `duplicate` (skipped, not an error) so a retry is safe, writes one audit row per import with the row counts and no cell contents, and applies all or nothing. Idempotency-Key supported.
Affected lanes: contracts, api-core (handlers), auth-scopes (scope checks), console (switches `import/apply.ts` to the bulk call and keeps the client-side check as a fast first pass).
Workaround meanwhile: client-side dry run, sequential create calls, stop at the first failure, duplicates skipped on re-check. Documented in `apps/console/src/import/apply.ts`.
