## Contract change requests

### A-09: Latin "PM" in Urdu times, and "PM" plus "بجے" together (done 2026-10-18, see Done)

Requested by: accessibility fix pass (user-app, admin-app, console lanes), 2026-10-18
Contract: i18n keys (new `time.period.*` keys); formatter code in three apps
Finding: `docs/quality/accessibility-rtl.md` A-09. Urdu screens show "ہر روز 9:00PM بجے" and "4:30 PM".

**Where it comes from.** It is not a translation. The apps format times with `Intl.DateTimeFormat` in the `ur-PK` locale with `hour: 'numeric', minute: '2-digit'`. In the Unicode CLDR data for Urdu, the short day period is the Latin "AM" and "PM", so the browser returns "9:00 PM". The places that do this:

- `apps/user-app/src/core/format.ts`: `formatKeepingTime`, used by `formatClockTime` and `formatLocalTime`, which feed `features/nearby/schedule.ts` (`describeWhen`, `describeWhenParts`) and `components/ReadAlongCard.tsx`
- `apps/admin-app/src/lib/time.ts`: `formatLocalTime` and `formatInstantTime` (`hour12: true`), used by the Today, Session, Occurrence, Attendance, Registrants, Updates and Schedule screens
- `apps/console/src/lib/posters.ts`: `formatLocalTime` (`ur-PK-u-nu-latn`, `hour12: true`)

The Urdu templates then add "بجے" ("o'clock") after the time: `session.schedule`, `session.schedule.everyDay`, `session.schedule.onDays`, `session.schedule.oneOff`, `poster.dailyAt` and `poster.onDateAt` are all "… {time} بجے". The result marks the time twice: "PM" (Latin) and "بجے". The missing space in "9:00PM" is the browser's narrow no-break space (U+202F) before "PM", which the Urdu font has no glyph for. A Latin "PM" also breaks guide §5, which writes the part of the day in Urdu before the figures: "رات 9:00 بجے".

The poster renderer already does it right (`apps/poster-renderer/src/format.ts`, `formatTime`): "ہر روز رات 9:30 بجے", using the keys `poster.period.*`.

**Proposed change.**

1. `packages/i18n` (this package): add one general namespace for the part of the day, with the same values and hour bands as `poster.period.*`, English and Urdu together, with the Urdu values marked as drafts for review:

   | Key                     | en   | ur (draft) | Hours (local) |
   | ----------------------- | ---- | ---------- | ------------- |
   | `time.period.lateNight` | `am` | `رات`      | 00:00–03:59   |
   | `time.period.morning`   | `am` | `صبح`      | 04:00–11:59   |
   | `time.period.noon`      | `pm` | `دوپہر`    | 12:00–15:59   |
   | `time.period.evening`   | `pm` | `شام`      | 16:00–18:59   |
   | `time.period.night`     | `pm` | `رات`      | 19:00–23:59   |

   Add `time` to the namespaces in `docs/engineering/i18n-keys.md` (contracts lane). Leave `poster.period.*` in place for the renderer until it moves to the new keys.

   Leave the six "… {time} بجے" templates as they are. Once `{time}` is "رات 9:00", they read "ہر روز رات 9:00 بجے", with "بجے" once. The templates without "بجے" (`readAlong.session`, `console.posters.source.*`, `admin.schedule.effect.when`, `admin.registrants.offline`) read correctly as "روزانہ رات 9:00" and need no change.

2. Then each formatter (owned by user-app, admin-app and console), for Urdu only: format the figures without a day period, as `h:mm` in 12-hour time with Latin digits, and put the Urdu period first:

   ```ts
   // Urdu: "رات 9:00", the figures isolated so they stay left to right inside Urdu text.
   const h12 = h % 12 === 0 ? 12 : h % 12;
   const clock = `${h12}:${String(m).padStart(2, '0')}`;
   return `${t(periodKey(h))} ${isolate(clock)}`; // periodKey: the hour bands in the table
   ```

   English stays as it is ("9:00 pm"). In `apps/user-app/src/core/format.ts`, `formatKeepingTime` keeps the isolate around the figures only; `formatDateTime` composes the date and the new time the same way.

**Tests to add with it:** the Urdu output has no Latin letters (`/[A-Za-z]/`), it is "رات 9:00" for 21:00, "صبح 5:15" for 05:15 and "دوپہر 12:30" for 12:30, and `session.schedule.everyDay` renders as "ہر روز رات 9:00 بجے" with "بجے" once.

**Affected lanes:** i18n keys (contracts for the key structure, ui for the wording review), user-app, admin-app, console. The Home screen's big time already splits the figures from the part of the day (A-10 fix, `apps/user-app/src/features/home/clock.ts`), and it handles a period before the figures, so it needs no change when this lands.

**Workaround meanwhile:** none. Urdu screens keep the Latin "PM" until this lands.
