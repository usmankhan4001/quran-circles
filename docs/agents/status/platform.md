## Restore drill findings fixed (2026-10-18)

From `docs/quality/restore-drill.md` (quality lane, provisional local drill). Edited only `infra/backup/` and `infra/README.md`. Not committed.

- **Finding 1 (high), `--replace` destroyed live data before knowing the backup was readable.** `restore.sh` now proves the whole set first, before anything is stopped: checksums, the manifest, a full `age -d` of the dump into a private work directory (mode 700, under `TMPDIR` if set, else `QC_BACKUP_DIR`, never `/tmp` by default, deleted on exit and pruned by `backup.sh` after a day if a run was killed), `pg_restore --list` on the decrypted file (in a throwaway container from the postgres image, file mounted read-only), and a full decrypt plus `tar -t` of the poster archive. Then `--replace` restores into a new database `qc_restore_new` and compares it with the manifest **while the stack keeps running**; only then it stops api and worker, takes the `pre-restore` backup, unpacks posters into `.restore-new` inside the volume, swaps the poster files by renames (undone on failure; a `.restore-swapping` marker tells the undo which phase it reached), and swaps the databases in one transaction (`qc` to `qc_before_restore`, `qc_restore_new` to `qc`). A failure before the swap leaves live data untouched and starts the stack again. `qc_before_restore` is kept until `restore.sh --cleanup` (new) or the next `--replace`. On failure: a `RESTORE FAILED` line with the step and whether live data was touched, an alert through `QC_ALERT_WEBHOOK_URL` (`alert` in `lib.sh`, as backups use), and, after the swap, the exact command to restore the `pre-restore` file. `--replace` refuses to start without a running stack (new server: deploy first) or with a `.restore-old` left by an interrupted run.
- **Finding 2 (medium), optional checksums.** `.sha256` is mandatory in `restore.sh` (both modes) for the dump, the poster archive and the manifest; `--allow-missing-checksum` only for old backups. The hash is now compared directly, not with `sha256sum --check`, which trusted the file name inside the `.sha256` (a `.sha256` naming a different, good file let a damaged file pass; test D). `restore-test.sh --remote` lists and fetches every file of the set without `|| true`; a failed download fails the test. It passes both `--allow-missing-*` flags on.
- **Finding 3 (medium), `--check` compared counts with nothing.** `backup.sh` writes `<name>.manifest` (+ `.sha256`) with each set: `format`, `backup <name>`, `table <name> <rows>` for every public table, `posters <files>`. Counts only. The row counts come from the same snapshot `pg_dump` uses: one read-only REPEATABLE READ psql session (a bash coprocess) exports its snapshot, `pg_dump --snapshot` dumps it, and the same session counts afterwards; the poster count comes from listing the archive stream on its way to `age` (a FIFO). Manifests follow the dumps into `weekly/`, the second location and retention. `restore.sh` validates the manifest's format, then fails on any table or count that differs (prints the differing names and counts only), on a poster count that differs, and on a poster archive that is missing while the manifest lists posters. `--allow-missing-manifest` only for old backups.
- **Findings 4 and 5 (low).** Every `restore.sh` run (check, replace, cleanup) ends with one `RESTORE OK` / `RESTORE FAILED` line and the time. `restore-test.sh --remote` uses a private mode-700 directory (TMPDIR respected, else `QC_BACKUP_DIR`), and now also reports FAILED (file and alert) when it fails before the check (for example nothing found in the second location), which it did not before.
- **Docs.** `infra/README.md`: manifest in "Backups"; "Restore" rewritten (what is checked first, the five steps of `--replace`, `--cleanup`, the flags, restoring onto a brand-new server: deploy first); new "Recovery targets (open: for the owner to accept)": RPO up to about 24 h (nightly logical dumps, no WAL archiving or point-in-time recovery), RTO minutes on a running server (drill: replace 16.5 s, check 7 s, restore-test 9.1 s, about 25 s download at 100 Mbit/s; the human's steps dominate), server loss not measured. Owner checklist item added.
- **`lib.sh`**: new `pg_image`, `in_pg_image`, `private_workdir`, `QC_COUNT_SQL`; `in_poster_volume` now uses `in_pg_image` (same flags as before).

### Tested (same method as the drill)

Throwaway Postgres 16.15 cluster from `/usr/lib/postgresql/16/bin` on a free port in a `/tmp` directory, run as `postgres`; real migrations (10) and the dev seed, plus 200,000 synthetic `audit_log` and 50,000 `message_outbox` rows (no phone numbers or names); 300 random poster files (20 MB, one in ten mode 0600, a subdirectory, owner uid 1000). Real `age` with a throwaway key in the scratchpad, shredded afterwards. Stand-in `docker`: `compose exec` runs the host's `pg_dump`/`pg_restore`/`psql`; `docker run` runs the command with the mount path rewritten, as uid 1000 via `setpriv`, and `:ro` mounts are real read-only bind mounts in a private mount namespace; `compose stop`/`up` are logged no-ops (with a switch to make `up` fail). Stand-in `rclone` on a local directory. Alerts delivered to a local webhook receiver. Live data compared with a fingerprint (per-table count and md5 of all rows, the `audit_log` sequence, path, mode, owner and sha256 of every poster file).

- Good backup: `backup.sh` writes dump, posters and manifest (41 tables, 300 files) and copies all six files to `weekly/` and the second location. `--check` passes against the manifest. After deleting 28,571 + 11,111 rows, 10 poster files and adding a stray file, `--replace` brings the live fingerprint back to the source exactly (7 s at this size), keeps `qc_before_restore`, alerts "restore OK". `--check` of the `pre-restore` set passes against its own manifest (the damaged counts, 291 posters).
- Refused by `--replace` with **no stop call and the live fingerprint unchanged**, no leftover database, `.restore-*` directory or work directory: corrupted dump without `.sha256` (refused for the missing checksum; with `--allow-missing-checksum`, refused at the decrypt), truncated dump (same), corrupted poster archive without `.sha256` (missing checksum; with the flag, refused at `tar -t`/decrypt), corrupted dump with `.sha256`, `.sha256` naming another good file, a valid age file that is not a dump (`pg_restore --list` refuses), a valid age file that is not a tar, manifest row count changed (`--replace` restores into `qc_restore_new`, the comparison fails, the new database is dropped, the stack is never stopped), manifest poster count changed, poster archive missing, manifest missing. Each sent a "restore FAILED ... (live data untouched)" alert.
- Manifest catches a mismatch: `--check` with one count changed prints `< table audit_log 200001` / `> table audit_log 200000` and fails.
- Snapshot consistency: a backup taken while a writer inserted 200-row batches (audit_log 204,600 before, 205,800 in the manifest, 219,600 after) passes `--check` with all 41 counts equal.
- Poster swap failing in phase 1 (an immutable live file) and in phase 2 (an immutable unpacked file): undone, live fingerprint equal to the state before, stack started again, "live data untouched".
- Stack failing to start after the swap: `RESTORE FAILED ... live data already replaced`, alert, the recovery command printed; running that command brought the live fingerprint back to the state before the failed restore.
- `--cleanup` asks for the project name, refuses a wrong one, drops `qc_before_restore`; a second run says there is nothing to do. A wrong name at the `--replace` prompt changes nothing.
- `restore-test.sh`: local and `--remote` pass; `--remote` work directory is mode 700 under `TMPDIR` when set and under `QC_BACKUP_DIR` when not, and is removed. Missing remote dump `.sha256`: FAILED and alert (passes with `--allow-missing-checksum`). Edited remote manifest: checksum mismatch, FAILED. Empty second location: FAILED written and alerted.
- shellcheck 0.11 clean on `infra/backup/*.sh`; `npx prettier --check infra/README.md` clean.
